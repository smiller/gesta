# A link to a line

Asked 2026-11-05, on the first look at the Punica's Book 1: a link in a book's Argument selected the line's words, which raised the format bar and marked the sentence's English, though that English translates several lines. "It would be neater if it just highlighted line 672."

REVIEW CYCLES: 2

## Decisions

- An address can name a line: `#bookshelf/…/Book%201?line=672`. It is a new payload beside `?h=`, which still selects words; references and contents links keep `?h=`.
- It calls the code ⌃⌘G calls ("call the same code", asked, after a first version copied part of it): `askLine` is what the Line box's words name on this page, stanza and line, paragraph, verse or line, and both route through it. Only what comes from there being no bar differs: the caret is placed at once, the mark ends at the next click or key that moves or writes (a bare modifier, ⌘C, leaving the window and a scrollbar do not), an ordinary landing says no word, though an omitted line and a refusal do, and before the warm the landing waits, the work's own page not yet read.
- Clicking the same link again marks the line again rather than saying "already here".
- In a `::: dual-language` block the mark is the row's band across both columns, for the links and ⌃⌘G alike (asked: "it should highlight both the text and translation of line 672"). A Latin-only mark was built first, on a misreading of his comment, and taken out the same day.
- The band crosses both columns on every row of a dual-language block, a row the English only runs down beside included (asked 2026-11-06, of ⌃⌘G 694: "It's supposed to highlight both halves"). The two gestures had the one code already; the row has no cell of its own to mark, its width stopping at the Latin column, and the first version's reading looked only at a row holding an English cell. The band marks the row's height across the English beside it, not the English sentence (asked: "the highlight of line 672 of the Latin and lines 672-74 of the English didn't make sense").
- A rename or re-file moves an address with what it names, the host's links and the page's own; the same for `?h=`, the same class. A delete removes them from the host.

- The corner names the block only where the number is in more than one ("I don't think we need that", asked 2026-11-06, of `line 421 — verse block 26 of 37`): the ordinal came over with ⌃⌘G from the old app (ac35960, 2026-08-06) for a page whose blocks each count from 1, and its test asked how many blocks the page has, so a page numbered straight on across 37 blocks spoke on every jump. A number in two blocks still says which, Enter walking them ("good with keeping the message when there are multiple verse blocks").
- On a page numbered straight on, the refusal reads `no line 695, the last line is 694` (asked 2026-11-06, in those words, of `no line 695 — the longest verse block ends at 694`). Blocks that repeat a number keep the longest block, "the last line" not being true of them: my reading of where the words hold, not asked. A first version also kept the longest block for a number in a gap between blocks; dropped the same day (asked: "this makes no sense").
